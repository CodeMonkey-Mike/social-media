01 Feature One

Native KRC-20 Tokens on Layer 1

Base-layer primitive

From Overlay to First-Class

Today's KRC-20 lives as inscription-style metadata coordinated off-chain via Kasplex. Toccata moves it into the protocol itself — tokens become real, native objects on the chain.

No more indexers

Direct, On-Chain State

Wallets and apps can read token balances directly from the node — no off-chain indexer required to determine who owns what. Faster, cheaper, more reliable.

Why It Matters

Native tokens are the foundation everything else sits on — DeFi, NFTs, lending, tokenized assets. Without them, builders can't ship a real ecosystem on Kaspa.

· Quick Definition

What's a Covenant?

The word is jargon borrowed from Bitcoin research — nothing to do with the everyday meaning of a promise between people. In a blockchain context:

A covenant is a rule attached to a coin that restricts how that coin can be spent in the future.

Today's UTXO

Normal Coins

When you receive coins, the only rule is: whoever has the private key can spend them however they want.

Once signed, the receiver has total freedom over those coins.

After Toccata

Covenant Coins

Coins arrive pre-bundled with rules about what can be done with them next. The coins themselves enforce the conditions.

  • → "Can only be sent to address X, Y, or Z"
  • → "Can't be spent until block 50,000,000"
  • → "Requires 2-of-3 specific signatures"
  • → "10% must route to this other address"
  • → "Can only move into another covenant with the same rules" ← this is how tokens work
02 Feature Two

Covenants via SilverScript

High-level language

Kaspa's Solidity

SilverScript is Kaspa's first high-level covenant language and compiler — designed to make writing covenants feel like "writing apps," not "fighting script." Intentionally narrower than Solidity.

No VM overhead

Compiles to Native

Unlike Ethereum, there's no virtual machine. SilverScript compiles straight to Kaspa Script opcodes — lean, fast, and aligned with the UTXO security model.

KIP-20

Covenant IDs

Underneath SilverScript, KIP-20 introduces consensus-tracked Covenant IDs — stateful covenants scale practically, with no recursive lineage proofs dragging parent history around.

03 Feature Three

Zero-Knowledge Verification on L1

KIP-16

ZK Opcodes + Precompile

Adds ZK opcodes with a verifier precompile subsystem — currently supporting a flexible Groth16 verifier with arbitrary parameters and verification keys.

A RISC Zero STARK verifier is already running on Testnet 12, with a final call pending on mainnet activation.

Privacy + scale

Verify Without Exposing

Applications can prove a computation or claim is true without revealing the underlying data — the foundation for privacy features and verifiable off-chain compute.

Combined with covenants, this is the bedrock for "based ZK applications" on Kaspa — including canonical L1↔L2 bridges.

04 Feature Four

vProgs Foundations

Plumbing, not product

The Long Game

vProgs (Verifiable Programs) = on-chain sequencing with off-chain execution settled via ZK proofs. Toccata ships the underlying script and ZK primitives that vProgs builds on top of.

2027 target

Composable Smart Contracts

The long-term destination: synchronously composable verifiable programs — Kaspa's answer to fully expressive smart contracts. Full rollout targeted for 2027 alongside the 100 BPS goal.

Translation

Toccata is not vProgs. Toccata is the plumbing that makes vProgs possible later.

05 Feature Five

Sequencing Commitments (KIP-21)

Canonical ordering

Partitioned Architecture

Introduces a partitioned sequencing commitment design — a reliable way for applications to reference and order data across the DAG. Essential for ZK rollups and bridges that need canonical transaction order.

Locked-in pricing

Script-Engine Economics

Finalizes gas and pricing for the new opcodes so miners, block builders, and developers know exactly what every operation costs the moment mainnet activates.

Why the May → June delay

KIP-21 is the reason. Sutton's team needed more time to lock the sequencing architecture before freezing it onto mainnet.
