# C1 VERTICAL · the AAARRR funnel map (Type 2 SYSTEM-DESIGN) · 1080x1920 · six placements in CH4

Portrait twin of `../../diagrams/C1.html` + `../../diagrams/_state-cues.md` (the 16:9 cue sheet). **Same 24 state ids, same
roles, same lit colour (`--accent-green` #00e68a, stylesheet default: no `chapter_themes`), same level grammar, same cue
times.** Only the layout and the type sizes change. Source `C1.html` (this folder); stills `C1-<state>.png`, each exactly
1080x1920; element boxes per state in `C1.geometry.json` (`elements.<state>.<data-k>`, stage px; `geom` = the layout
table). Shot by `../_build_vertical.py C1` (fonts awaited, em/en dash refused, 48 px text margin, no visible text overlap).

**Pixel contract (verified by diff, `_previews/chart-build-vertical/C1-contract.json`):** every shared element sits at the
same pixels in every state; a swap changes only an element's level. The only off-element differences are a few anti-alias
pixels on the number badges (under 20 of 255, invisible). So every swap below is a spotlight over shared pixels.

**Design calls worth Mike's eye.** (1) The funnel flows DOWN, the natural portrait funnel. (2) The 16:9 put each role's label
directly above its bracket; portrait has no room beside the funnel for a 30 px label, so labels 1 and 2 sit in the band
above and their brackets carry the matching number badge (1, 2) as the link. Roles 3 and 4 keep their label on their own
shape. (3) The platform's "floor with an arrow into every stage" becomes the floor plus a riser up the left side that feeds
each stage sideways (perpendicular to the flow, exactly as the 16:9 arrows were); brackets stay on the right, so nothing
crosses. (4) The GTM lane sits under REVENUE (the flow continues down into the sales side), linked up into REVENUE.
(5) Every text that carries meaning is 19 px or more (role labels 30, OWNS 24, stage names 24, chips 21), sized for a
phone held upright.
