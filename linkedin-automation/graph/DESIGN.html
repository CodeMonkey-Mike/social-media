Graph state (bookkeeping only)

class LaneState(TypedDict):
    group_id: str          # "6665791"
    names: list[str]       # seed targets, e.g. ["Wade", "Wyatt"]
    seeded: dict          # {matched, new, per_name}  ← verify_seed
    status: str           # running | done | failed | halted_restricted
    error: str | None     # last stderr tail for diagnosis

State never exclusively carries anything a downstream manual step needs — the JSON files remain the contract. Delete the checkpoint DB and nothing downstream breaks.

Hard rules → enforced by structure, not memory

Rule (linkedin-automation/CLAUDE.md)How the graph enforces it
One Chrome instance, lanes sequential Strictly linear edges — the topology has no parallel branch that could touch li-bot-profile twice.
One attempt per run, never relaunch Node retry policy = 0. Failure routes to HALT, carrying the stderr tail for diagnosis.
STOP on restriction page, rest of day RESTRICTED in wrapper output → HALT edge. The graph cannot structurally continue past it.
Human typing + pacing in the search box Live inside the wrapped script, untouched — wrapping at batch granularity means the quirks travel with the code.
Volume budget (Lane 2: ≤50 scrape/day) The per-run --max=N from Mike's "Lane 2, N" ask is the human decision — an argument, not an interrupt() (decided 2026-07-28). The CLI hard-refuses --max>50; the kill-switch stops a systemically failing run instead of letting the frozen JS grind on.
